# Практическая работа №2, вариант 19

Дисциплина «Конфигурационное управление», ИКБО-42-25.
Инструмент анализа зависимостей Rust/Cargo на Python 3.11+.
Используется только стандартная библиотека Python.

## Этап 1. Конфигурация

Запуск из корня проекта:

```sh
sh run.sh examples/test.toml config
make test
make check
```

Команда `config` выводит шесть параметров в формате `ключ=значение`.
Настройки хранятся в TOML: `package`, `repository`, `test_mode`,
`version`, `ascii_tree`, `exclude`. Относительный путь репозитория
разрешается относительно TOML-файла. Неверные значения, типы,
неизвестные и отсутствующие ключи вызывают ошибку с кодом 1.
Ошибки синтаксиса CLI возвращают код 2.

Сборка не требуется. Для проверки синтаксиса используйте `make check`.
Тесты запускаются встроенным `unittest`, установки пакетов не требуется.

## Этап 2. Прямые зависимости Cargo

```sh
sh run.sh examples/itoa.toml direct
```

`Registry` получает JSON Lines из HTTP sparse index, строит адрес по
правилам Cargo и выбирает точную корневую версию. `direct` выводит
имена, требования версий, тип, optional и target прямых зависимостей.
Обрабатываются переименования через поле `package` и ошибки HTTP/JSON.
Данные кэшируются в памяти. `versions.py` самостоятельно обрабатывает
SemVer, prerelease, caret, tilde, wildcard и пересечения сравнений.

Политика анализа: все объявленные normal/build зависимости, включая
optional и зависимости для всех платформ; dev зависимости исключены.
Это граф деклараций, а не полный resolver Cargo с активацией features.
Внешние registry в зависимостях явно отклоняются.

Формат индекса: [Cargo Book](https://doc.rust-lang.org/cargo/reference/registry-index.html).

## Этап 3. Рекурсивный DFS

```sh
sh run.sh examples/test.toml graph
sh run.sh examples/cycle.toml graph
sh run.sh examples/filtered.toml graph
```

`build_graph` помечает вершину до рекурсивного спуска. Циклы и петли
сохраняются, но повторно не раскрываются. Вершина содержит имя и версию.
Для каждого ребра выбирается максимальная подходящая неотозванная
версия; унификации версий через Cargo.lock нет.

`exclude` исключает имена с заданной подстрокой до получения их метаданных.
Сравнение чувствительно к регистру. Пустая строка отключает фильтр.
Исключение корневого пакета считается ошибкой конфигурации.

Тестовый репозиторий: JSON-объект `{"A": ["B"], "B": []}`.
Все имена состоят из больших латинских букв, все упомянутые вершины
должны быть явно определены. Версия из TOML назначается всем вершинам.
Примеры включают ромб, несвязанные вершины, цикл, петлю и фильтрацию.

## Этап 4. Обратные зависимости

```sh
sh run.sh examples/test.toml reverse --target D
sh run.sh examples/test.toml reverse --target Z
sh run.sh examples/cycle.toml reverse --target A
sh run.sh examples/filtered.toml reverse --target D
```

`reverse_dependencies` транспонирует граф и вызывает тот же
`recursive_dfs`, что используется для прямого обхода. Выводятся прямые
и транзитивные зависимые пакеты, без самого запрошенного пакета.
`--target` выбирает объект запроса (имя или `имя@версия`), по умолчанию
это корневой пакет из TOML. Неоднозначное имя требует указания версии.

Область поиска явно выводится в заголовке. В тестовом режиме это весь
конечный репозиторий, включая компоненты вне корневого пакета.
Для реального sparse index это транзитивный граф корня из TOML:
HTTP sparse index не позволяет перечислить все существующие пакеты.
Например, можно найти, кто зависит от `memchr` внутри `regex`.
Это не глобальный поиск по всему crates.io. Фильтр действует до поиска.
