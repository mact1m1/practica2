# Практическая работа №2, вариант 19

Дисциплина «Конфигурационное управление», ИКБО-42-25.
Инструмент анализа зависимостей Rust/Cargo на Python 3.11+.
Используется только стандартная библиотека Python.
Реализованы все пять этапов: TOML, чтение Cargo sparse index,
рекурсивный DFS, обратные зависимости, Graphviz и ASCII.

## Настройки и интерфейс

```sh
sh run.sh examples/test.toml graph
sh run.sh examples/test.toml reverse --target D
```

Все шесть ключей TOML обязательны, неизвестные ключи запрещены.
Настройки анализа берутся только из файла. CLI выбирает TOML,
операцию `config`, `direct`, `graph`, `reverse` и объект обратного запроса.

| Ключ | Тип | Значение |
| --- | --- | --- |
| `package` | строка | Имя корня; в тестовом режиме только A-Z |
| `repository` | строка | Корень HTTP(S) sparse index или путь к JSON |
| `test_mode` | bool | `true` включает автономный JSON-репозиторий |
| `version` | строка | Точная SemVer-версия корня, например `1.4.2` |
| `ascii_tree` | bool | Дополнительное ASCII-дерево для команды `graph` |
| `exclude` | строка | Подстрока исключаемых имён; `""` выключает фильтр |

`repository` в реальном режиме: например `https://index.crates.io`.
Git-индекс, crates.io API URL, префикс `sparse+`, query и авторизация
не поддерживаются. В тестовом режиме путь JSON считается от TOML.

Запуск из любого каталога поддерживается: передайте абсолютный путь
к `run.sh` и TOML. Интерпретатор выбирается через `PYTHON=python3.12`.
На Windows задайте `$env:PYTHONPATH="src"` и выполните
`python -m cargograph examples/test.toml graph` в PowerShell.

На некоторых установках Python в macOS отсутствует настроенное
хранилище CA. При ошибке сертификата используйте системное хранилище:

```sh
SSL_CERT_FILE=/etc/ssl/cert.pem sh run.sh examples/itoa.toml direct
```

Проверка TLS в программе не отключается.

## Этап 1. Конфигурация

Запуск из корня проекта:

```sh
sh run.sh examples/test.toml config
make test
make check
```

Команда `config` выводит шесть параметров в формате `ключ=значение`.
Настройки хранятся в TOML: `package`, `repository`, `test_mode`,
`version`, `ascii_tree`, `exclude`. Относительный путь репозитория
разрешается относительно TOML-файла. Неверные значения, типы,
неизвестные и отсутствующие ключи вызывают ошибку с кодом 1.
Ошибки синтаксиса CLI возвращают код 2.

Сборка не требуется. Для проверки синтаксиса используйте `make check`.
Тесты запускаются встроенным `unittest`, установки пакетов не требуется.

## Этап 2. Прямые зависимости Cargo

```sh
sh run.sh examples/itoa.toml direct
```

`Registry` получает JSON Lines из HTTP sparse index, строит адрес по
правилам Cargo и выбирает точную корневую версию. `direct` выводит
имена, требования версий, тип, optional и target прямых зависимостей.
Обрабатываются переименования через поле `package` и ошибки HTTP/JSON.
Данные кэшируются в памяти. `versions.py` самостоятельно обрабатывает
SemVer, prerelease, caret, tilde, wildcard и пересечения сравнений.

Политика анализа: все объявленные normal/build зависимости, включая
optional и зависимости для всех платформ; dev зависимости исключены.
Это граф деклараций, а не полный resolver Cargo с активацией features.
Внешние registry в зависимостях явно отклоняются.

Формат индекса: [Cargo Book](https://doc.rust-lang.org/cargo/reference/registry-index.html).

## Этап 3. Рекурсивный DFS

```sh
sh run.sh examples/test.toml graph
sh run.sh examples/cycle.toml graph
sh run.sh examples/filtered.toml graph
```

`build_graph` помечает вершину до рекурсивного спуска. Циклы и петли
сохраняются, но повторно не раскрываются. Вершина содержит имя и версию.
Для каждого ребра выбирается максимальная подходящая неотозванная
версия; унификации версий через Cargo.lock нет.

`exclude` исключает имена с заданной подстрокой до получения их метаданных.
Сравнение чувствительно к регистру. Пустая строка отключает фильтр.
Исключение корневого пакета считается ошибкой конфигурации.

Тестовый репозиторий: JSON-объект `{"A": ["B"], "B": []}`.
Все имена состоят из больших латинских букв, все упомянутые вершины
должны быть явно определены. Версия из TOML назначается всем вершинам.
Примеры включают ромб, несвязанные вершины, цикл, петлю и фильтрацию.

## Этап 4. Обратные зависимости

```sh
sh run.sh examples/test.toml reverse --target D
sh run.sh examples/test.toml reverse --target Z
sh run.sh examples/cycle.toml reverse --target A
sh run.sh examples/filtered.toml reverse --target D
```

`reverse_dependencies` транспонирует граф и вызывает тот же
`recursive_dfs`, что используется для прямого обхода. Выводятся прямые
и транзитивные зависимые пакеты, без самого запрошенного пакета.
`--target` выбирает объект запроса (имя или `имя@версия`), по умолчанию
это корневой пакет из TOML. Неоднозначное имя требует указания версии.

Область поиска явно выводится в заголовке. В тестовом режиме это весь
конечный репозиторий, включая компоненты вне корневого пакета.
Для реального sparse index это транзитивный граф корня из TOML:
HTTP sparse index не позволяет перечислить все существующие пакеты.
Например, можно найти, кто зависит от `cfg-if` внутри `crc32fast`.
Это не глобальный поиск по всему crates.io. Фильтр действует до поиска.

## Этап 5. Graphviz и ASCII

```sh
sh run.sh examples/itoa.toml graph
sh run.sh examples/crc32fast.toml graph
sh run.sh examples/miniz_oxide.toml graph

# DOT в stdout, ASCII в stderr: результат легко сохранить раздельно.
sh run.sh examples/test.toml graph > graph.dot 2> tree.txt
sh run.sh examples/dot-only.toml graph > graph.dot

# Необязательное создание изображения через Graphviz.
dot -Tpng graph.dot -o graph.png
```

Сам Graphviz нужен только для последней команды, анализатор работает
без него. DOT сохраняет все вершины и рёбра, включая циклы.
ASCII помечает циклы `[cycle]`, уже раскрытые общие ветви `[shared]`.
Имена и рёбра сортируются для воспроизводимого вывода.

Сохранённые DOT, ASCII, манифесты и фактический вывод `cargo tree`
для трёх различных пакетов: [сравнение](docs/COMPARISON.md).
В отчёте объясняются расхождения, включая optional-зависимости.
Реальные метаданные получены программой напрямую через HTTP;
Cargo применялся только отдельно для сравнения.

## Функции и структура

Полные описания классов, методов и функций:
[справочник API](docs/API.md), а также docstring в исходниках.

| Модуль в `src/cargograph/` | Назначение функций |
| --- | --- |
| `config.py` | Чтение TOML, проверка типов/значений, пути и URL |
| `versions.py` | SemVer, требования Cargo, сравнение и верхние границы |
| `registry.py` | HTTP, shard-пути индекса, точные и подходящие версии |
| `testrepo.py` | Чтение, проверка и перечисление тестового репозитория |
| `graph.py` | Построение, общий DFS, транспонирование, выбор цели |
| `render.py` | Экранированный Graphviz DOT и ASCII с маркерами |
| `cli.py` | Разбор CLI, диспетчеризация, обработка ошибок |

`src/` содержит исходники, `tests/` — автономные тесты,
`examples/` — TOML и JSON, `docs/` — демонстрации и сравнение.
Тесты проверяют все настройки, HTTP/JSON-ошибки, SemVer, DFS, циклы,
фильтрацию, разные версии, обратные запросы, DOT и CLI из другого каталога.
Тесты не обращаются к внешней сети. Без Make их можно запустить так:

```sh
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

## Ограничения

Это граф объявленных normal/build зависимостей: Cargo features,
Cargo.lock, ограничения версии Rust и унификация версий не моделируются.
Для одного пакета могут присутствовать несколько версий в графе.
Prerelease выбирается только при явно подходящем prerelease-требовании.
Точную отозванную версию корня можно исследовать, при выборе
транзитивных версий отозванные релизы исключаются.

Размер одного файла индекса ограничен 32 MiB, тайм-аут HTTP — 30 секунд.
Кэш действует в памяти в пределах запуска. Очень глубокий граф ограничен
стеком Python и возвращает ошибку; большие графы требуют много запросов.
Версии реестра меняются, поэтому сохранённые примеры фиксируют
результат на дату проверки, указанную в отчёте.

## История этапов

Пять этапов сохранены отдельными Conventional Commits.
Метки `stage-1` ... `stage-5` позволяют открыть состояние любого этапа:

```sh
git log --oneline --reverse
git show stage-1:README.md
```

Фактические демонстрации этапов и ошибок: [DEMO.md](docs/DEMO.md).
Бинарные файлы, кэши, окружения, изображения и архивы не добавлены в Git.
DOT-примеры сохранены как обычный текст.
